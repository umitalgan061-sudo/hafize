# Verified release tools

Adds owner-session gated `github_release` with server-configured standing authorization for the explicitly named project in the current owner request; no per-action prompt. Open a ready PR, validate exact SHA, same repo, safe branch, main base, complete file list, fixed CI workflow and clean mergeability, recheck immediately before merge, squash merge. Allowlisted paths initially Hafize UI and Borsa frontend/worker; other files, workflows, credentials and policy are blocked. Dispatch fixed Hafize Firebase or Borsa Cloudflare workflow at current main under the same explicit task authorization. Dispatch is not success; exact CI and live marker must be verified. `github_inspect jobs` returns job/step status. Existing browser rendering and orchestrator resume may be used when configured. Render API/hook, full browser interaction, draft conversion, arbitrary repo release and durable long-running restart recovery are not implemented here. No deployment credential is exposed or configured by this PR.

`HAFIZE_GITHUB_RELEASE_AUTONOMY=true` enables this only for authenticated primary-owner sessions already configured for safe GitHub autonomy. The current user message must identify an unambiguous supported project and explicitly request the corresponding release action. No model, tool output or external page can set authorization. Out-of-scope operations fail without prompting.
