# Kalıcı GitHub görev günlüğü (Upstash REST)

Optional, disabled when both environment variables are absent. Set UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN in Render's server environment, never in the browser or repository. Requires a stable existing HAFIZE_MASTER_KEY (or supported stable auth-key fallback). Partial/invalid configuration or unavailable Redis blocks durable GitHub tasks rather than falling back to unsafe writes. The rest of the app does not require Redis.

One opaque HMAC-named, AES-GCM encrypted latest checkpoint per owner/conversation; atomic compare-and-set detects overlap between deployments. Pending mutation intent and prepared file hash must be acknowledged before any external mutation. Terminal records without pending writes expire after 30 days; running or unresolved records are retained. A running record has a five-minute admission lease renewed on each checkpoint. A stale lease permits a read-only recovery turn, never a mutation replay. A subsequent explicitly authorized development turn can continue after reconciliation. This is not unattended job resumption or full persistent chat memory. Existing browser backup is still available; configured Redis is authoritative when a remote record exists. Only new tasks/checkpoints after deployment are remotely saved.

Free storage and command quotas depend on provider plan; monitor usage, keep eviction disabled, and do not expose tokens. Verification: CI, deploy, then perform a small authorized GitHub task, verify Redis keys/command activity without revealing values, interrupt after a verified checkpoint and continue from same conversation. The health metadata indicates configuration only, not successful remote access.
