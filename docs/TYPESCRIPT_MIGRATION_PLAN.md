# TypeScript migration plan

## Scope

Hafize already uses TypeScript for typed API/runtime modules. This migration extends that boundary into the remaining browser application core instead of introducing a second frontend framework.

## Runtime baseline

The project targets Node 24 LTS for server execution, Vite for browser bundling, and TypeScript 7 for static analysis. Node 24 has stable built-in TypeScript type stripping, while the repository build continues to use the TypeScript compiler for full type checking. The browser output remains standards-based JavaScript generated by Vite.

## Rules

- Keep the existing DOM and storage behavior stable while types are introduced.
- Prefer `unknown` at storage/API boundaries and narrow explicitly.
- Model conversation, message, tool activity, and agent records as interfaces.
- Do not add runtime dependencies solely for type support.
- Keep legacy entrypoints only until the typed bundle is proven equivalent.
- Remove a legacy entrypoint only after build and smoke contracts confirm the replacement.

## Completion criteria

A migrated module must have strict TypeScript checking, deterministic tests for its public boundaries, an explicit browser entrypoint, and a rollback path to the previous JavaScript entrypoint.
