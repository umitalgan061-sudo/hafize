# Composer History — Threat Model

## Assets

- Kullanıcının geçmiş composer mesajları.
- History retention settings.
- Backup JSON files generated by user.

## Trust boundaries

Browser composer is user-controlled input.

localStorage is untrusted mutable state.

Imported files are untrusted external input.

The backend is outside this feature's storage path.

## Threats

### XSS via history

Risk: malicious stored text is rendered as markup.

Mitigation: textContent/createElement only.

### Oversized storage

Risk: large local state causes UI or quota pressure.

Mitigation: 40 records, 12k per record, 512 KB import.

### Data exfiltration

Risk: history silently sent to a remote service.

Mitigation: no fetch/XHR/WebSocket and dedicated source test.

### Unwanted submission

Risk: selecting a history item sends it automatically.

Mitigation: selection only changes composer value.

### Shortcut interference

Risk: arrow keys break text editing or IME.

Mitigation: edge-only cursor detection and composition guard.

### Storage poisoning

Risk: malformed settings change retention unexpectedly.

Mitigation: allowlisted retention values and fail-closed defaults.

### Backup poisoning

Risk: malformed import removes current records.

Mitigation: parse and normalize before mutation; bounded input.

### Privacy residue

Risk: user disables history but old records remain.

Mitigation: disabled mode removes the history storage key.

## Out of scope

Account sync.

Cross-device history.

Server-side retention.

Conversation analytics.

## Security gate

Any future remote synchronization requires a new architecture and privacy review; it must not be slipped into this module as a convenience change.
