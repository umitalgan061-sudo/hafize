# Exact release and recovery

Separate Borsa Hosting and Worker CI/deploy targets. Publication requires successful exact-current-main CI evidence (Borsa test job, Hafize quality workflow), rechecks main, and passes expected_sha to the fixed workflow. Deployment workflows reject branch/commit mismatch. A queued dispatch is not live proof. Existing PR lookup avoids duplicates; draft conversion remains a GitHub UI action. A user-requested rollback_pr prepares a new ready PR for the latest exact main commit only, and only if it changes existing permitted text files. It restores the single parent contents using validated blob SHA, rejects additions/deletions/renames/protected files/incomplete diffs, validates all old contents before writes, and leaves merge/CI/publish separate. If a mutation becomes uncertain, inspect the branch instead of replaying it. No direct production rollback or permission escalation. Borsa wrangler configuration is excluded from automatic release. Borsa frontend release marker checked on both known hosts; not proof of authenticated data access. Requires corresponding Borsa workflow deployment (#11); no GPU or paid services provisioned.
